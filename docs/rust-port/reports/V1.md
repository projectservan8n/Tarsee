Names and shapes that are not the obvious translation:

- **`TTSEngine` class** is the trait `TtsEngine` (async_trait, object safe; the engine in use is an
  `Arc<dyn TtsEngine>`). Required: `name`, `synthesize(text, voice_id, &SynthOptions)`. Defaults are the base
  class's answers: `clone_voice` and `synthesize_stream` fail "Not implemented", `list_voices` is empty,
  `is_available` false. The optional JS methods V2 needs are trait methods with no-op defaults: `can_stream` (the
  JS `if (!engine.synthesizeStream)`), `default_voice`, `set_speed`, `warm`, `stop`. Results: `Synthesized { audio:
  Bytes, content_type }`, `AudioStream { stream: ByteStream, content_type }`, `VoiceInfo { id, name, is_clone,
  preview }` (serializes as `{id, name, isClone}`; `preview` only for ElevenLabs, `null` when none),
  `ClonedVoice { voice_id, name }` (`{voiceId, name}`). Errors are `TtsError { message, status, code }` (the JS
  `{ status: 501 }`, `{ code: "EMPTY_TEXT" }`).
- `tts_interface.rs` also holds three helpers the engines share (V2's Phonon may use them): `os_tmpdir(&Env)`
  (`os.tmpdir()` from the app's environment), `find_program`/`program_command` (a program on the app's `PATH`,
  started with exactly the app's environment, no console window on Windows, killed when dropped), and
  `exec_file` (`execFileSync` with Node's error texts: "spawnSync X ENOENT", "spawnSync X ETIMEDOUT",
  "Command failed: X args").
- **Installer errors** are one type, `install_common::InstallError { message, code, http_status, cause }`, used by
  install_common, tar_extract, whisper_models and python_runtime. Codes as in Node: HOST_REFUSED, HASH_MISMATCH,
  LOCKED, BAD_ARCHIVE, UNKNOWN_MODEL, NO_PYTHON. `cause` is the network error, which `describe_fetch_error` reads.
- **`guardedFetch(sources, fetch)`** is `guarded_fetch(&[OfficialHost], Arc<dyn Fetch>) -> GuardedFetch`. Its
  refusals must keep their code, which `FetchError` cannot carry, so downloads go through a small trait,
  `Downloader` (`get(FetchRequest) -> Result<FetchResponse, InstallError>`), implemented by `GuardedFetch` and by
  every `Fetch`. `download_file<D: Downloader + ?Sized>(&D, DownloadFile)`; pass `&*app.fetch()` for a plain one.
  `OFFICIAL_HOSTS.huggingface` / `.github` keep their names.
- **`downloadFile({...})`** is `download_file(fetch, DownloadFile::new(url, dest).sha256(..).size(..).progress(&f))`,
  returning `Downloaded::Kept` or `Downloaded::Fetched(sha256)` (the JS "kept" or the hash). `DownloadFile` has one
  field Node did not: `stall` (60 s), so a test need not wait a minute (tokio's `test-util` was not enabled when
  this was written; it is now, but the field does no harm).
- **`acquireLock(root, what)`** is `acquire_lock(&App, root, Option<&str>) -> InstallLock`. The Node module's
  `_heldLocks` set is the app service `HeldLocks`. The lock is released by `release()` or when dropped.
- **`extractTarGz(file, dest, { strip })`** is `extract_tar_gz(file, dest, strip) -> ExtractCounts { files, dirs,
  links }` (the work runs in `spawn_blocking`; `extract_tar_gz_blocking` is the same on the calling thread).
- **whisper_models**: the catalog is `WHISPER_MODELS: LazyLock<Vec<WhisperModel>>` in Node's key order, and every
  function that took `catalog` takes `&[WhisperModel]`. `findWhisperModel` gives `Option<FoundModel { name, dir,
  source: ModelSource }>` (source serializes "downloaded"/"image"/"cache"); `dirs` is `ModelDirs { models, bundled,
  caches }`. `downloadWhisperModel(name, root, { fetch, onProgress, log, retryDelayMs, catalog })` is
  `download_whisper_model(name, root, Arc<dyn Fetch>, DownloadModelOptions)`: the fetch is a required argument
  (Node fell back to the global `fetch`). `deleteWhisperModel` gives `DeletedModel { removed, kept }`.
- **The Docker build's command**: `run_download_command(Arc<dyn Fetch>, &args) -> i32` does exactly what the
  module's terminal block did (usage and exit 2, progress every 10%, `[stt]` lines, exit 0 or 1). See "Changes
  needed outside this package" for the CLI entry.
- **python_runtime**: a Python is `PythonRef { cmd, args, source, label }`; a probe is `PythonProbe { python:
  PythonRef (flattened), found, usable, version, executable, venv, faster_whisper, problem }`, which serializes as
  the JS object did. `pythonHome()`, `standaloneDir()`, `standaloneReady()` take `&Config`. `interpreterIn(dir,
  platform)` and `venvInterpreter(dir, platform)` are `interpreter_in(&Path)` / `venv_interpreter(&Path)` for this
  computer plus `interpreter_in_for(&str, platform)` / `venv_interpreter_for` for another OS (as the tests use).
  `pythonTarget({platform, arch, glibc})` is `python_target(&TargetQuery) -> Result<triple, plain-words error>`;
  `TargetQuery::current()` is the default (`process.platform` / `process.arch` are `node_platform()` /
  `node_arch()`). `runPython(ref, args, { timeout, env, onLine, cwd })` is `run_python(&App, ref, args,
  RunOptions)`, failing with `PythonRunError { message, code, exit_code, signal, timed_out, stdout, stderr }`.
  `spawnPython` is `spawn_python(&App, ref, args, SpawnOptions { env, cwd })` (all three pipes) and, for callers
  that want other stdio, `python_command(&App, ref, args, env) -> tokio::process::Command`. `ensureBasePython(opts)`
  is `ensure_base_python(&App, &EnsureOptions)`. **`__setForTests({ spawn, candidates })`** is
  `set_for_tests(&App, PythonOverrides { spawn: Option<SpawnHook>, candidates })`, kept in the app; a `SpawnHook`
  rewrites a `Launch { program, args, env }` (the fake Python's hook is `tests/it/fake_python.rs`, for V2's tests
  too).
- **Engines' constructors**: `EdgeTtsEngine::new(voice)` (+ `with_endpoint`, `with_timeouts`, `with_retry_delay`,
  `with_clock` for tests); `ElevenLabsTtsEngine::new(fetch, api_key, model_id, default_voice)`;
  `PiperTtsEngine::new(&Env, default_voice)`. Piper's module functions take the `&Env` they read the folder from:
  `voices_dir`, `save_piper_voice`, `delete_piper_voice`, `list_piper_voices` (`{ id, sizeMB, file }`).
- **whisper_engine** functions take `&App`: `is_available`, `transcribe(app, audio, model) -> Transcript { text,
  language }`, `download_model`; errors are `anyhow` (callers only report them).
- **Edge TTS protocol**: `generate_sec_ms_gec_token_v2(unix_seconds)`, `connect_url`, `speech_config_message`,
  `ssml_message`, `audio_payload` are public so the protocol can be checked piece by piece (fix round 1: these
  replaced `generate_sec_ms_gec_token(now_ms)` and `audio_of`; see "Fix round 1").

## Differences from the Node behaviour

- **Error texts from the network and the OS** come from Rust, not Node: `could not reach huggingface.co (<cause>)`
  carries reqwest's cause, not undici's `ENOTFOUND`; a request timeout reads "(the request timed out)" not "(The
  operation was aborted due to timeout)"; a file error reads "No such file or directory (os error 2)" not
  "ENOENT: no such file or directory, open '...'" (except Piper's missing wav, where Node's text is rebuilt); a
  gzip error reads zlib's words for the common cases since fix round 1 ("incorrect header check", "unexpected end
  of file", "incorrect data check") and flate2's otherwise; a WebSocket connection failure reads tungstenite's
  text (an HTTP refusal is mapped to ws's "Unexpected server response: N").
- **Edge TTS** keeps the audio in memory instead of a temporary `/tmp/edge-tts-*.mp3`, and `is_available` is
  always true (Node checked that the library could be loaded). The handshake does not offer
  `permessage-deflate`, which the `ws` library offered by default (tungstenite cannot read compressed frames; the
  service answers without it). Since fix round 1 it speaks node-edge-tts **1.2.12**'s protocol, not the pinned
  1.2.10's, which the service now refuses: see "Fix round 1", finding 4.
- **Piper** finds `piper` on the app's `PATH` directly. Node ran `which piper` through a shell, which never worked
  on Windows (cmd has no `which`), so Piper was never available there. *(Corrected in fix round 1: as first
  delivered, the Rust lookup read `PATH` case-sensitively, so with Windows' usual `Path` it found nothing either,
  as the review showed. Since the foundation's `Env` matches names in any case on Windows, it does find piper
  there; `tests/it/voice.rs` `a_program_is_found_on_a_path_spelled_in_any_case` covers it.)* Piper's and
  Edge's temporary files were a literal `/tmp/...` in Node (the current drive's `\tmp` on Windows); Piper now uses
  the OS temporary folder from the app's environment (the same as `/tmp` on Linux).
- **whisper.cpp**: `os.cpus().length` is `available_parallelism()` (which respects CPU limits; still capped at 4).
- **run_python** decodes output as a stream, so a character split between two reads is kept whole (Node decoded
  each chunk alone). Dropping a run, or a spawned worker's `Child`, kills the process (Node had no way to drop a
  promise).
- **Install lock**: "is that pid alive" is `kill(pid, 0)` on Unix (libc) and OpenProcess/GetExitCodeProcess on
  Windows, as libuv does. The held-locks set is per app, which is per process in production.
- **ElevenLabs**: a voice in the list without `voice_id` or `name` gets "" (Node left the field out). The multipart
  boundary is in undici's style but not undici's exact digits.
- `run_download_command` logs through `log::` (as the design says for `console.*`) and still prints Node's usage
  line, "usage: node whisper-models.js download <model> <folder>"; the CLI package may want its own wording.

## Looks like a bug in the Node code (ported as it is)

- `piper-engine.js` `deletePiperVoice(voiceId)` joins the id from the URL into a path unchecked: `../x` deletes
  `x.onnx` and `x.onnx.json` outside the voices folder (`routes/voice.js` passes `req.params.id`). *Not ported as
  it is since fix round 1:* by the design's "Joining paths" rule an id that is not one plain name deletes nothing.
- `edge-tts-engine.js` (through node-edge-tts 1.2.10): once the connection drops, nothing ends the turn until the
  library's 10-second timer says "Timed out"; the engine then rejected with a string, not an Error. A binary frame
  without `Path:audio\r\n` is taken from byte 11 (`indexOf` gave -1). (1.2.12, which the port now follows, fixed
  both.) Every voice is sent inside `xml:lang="zh-CN"` (the library's default; Tarsee never set `lang`).
- `whisper-engine.js` is imported by nothing. Its temporary names come from `Date.now()`, so two transcriptions in
  the same millisecond share files; a failed ffmpeg run leaves its wav behind; the model name is joined unchecked
  (since fix round 1 a name that is not one plain name is refused, by the "Joining paths" rule).
- `tar-extract.js` reads GNU base-256 numbers ignoring the low 7 bits of the first byte (only right below
  256^(len-1)).
- `elevenlabs-engine.js` `listVoices` answers `[]` for an HTTP error but throws for a network error.
- `install-common.js` describes a 60-second stall as "no data for 60s" (the abort reason), not through
  `describeFetchError`'s "stopped (...)" wording, since the reason is a plain Error.

### Public names and behaviour V2 should know about

  signatures did not change.
- New helpers in `install_common`: `remove_all`, `remove_all_async`, `remove_file_force` (Node's

  `is_plain_name`.
- Behaviour changes:
  - `delete_whisper_model` now fails when a folder cannot be removed.
  - `download_file`, `acquire_lock`, the Python download and the extractor's cleanup now fail where `fs.rmSync`

  - `delete_piper_voice` ignores an id that is not one plain name.
  - `whisper_engine` refuses a model name that is not one plain name.
  - `speech_text::js_trim` and `is_js_space` keep their names and now call `util::js`. They give the same answers.

### Findings

1. **Critical, NEL in a checksum field.** `octal` uses `util::js::trim`, and `parse_int` uses
   `util::js::trim_start`. A field with U+0085 is now NaN, as in Node, and the archive is refused as damaged. Test:
   `tar_extract::a_checksum_field_with_a_next_line_character_is_not_a_number`, on the reviewer's archive. Other
   `trim`s on outside text that I replaced:
   - `install_common`: the Content-Length header now goes through `js_number_text`, which is `Number()`. It now also
     refuses "inf" and "nan" and reads "0x10" as 16.
   - `python_runtime`: `last_lines` and `js_number`.
   - The fake Python in `testbin/fake_python.rs`.

   Tests: `install_common::numbers_read_as_javascript_s_number_reads_them`,
   `python_runtime::path_is_found_in_any_case_on_windows_and_lines_trim_as_javascript_does`, and
   `speech_text::trim_and_collapse_use_javascript_whitespace`. The last one now checks every BMP character's
   regex class against `util::js::is_whitespace`.
2. **Critical, pax length of 2^64 or more.** `parse_pax` now works in doubles, as the JavaScript did. The record's
   end is clamped to the data, as `subarray` clamped it, and a next position past the end stops the loop. Nothing
   overflows in debug or release builds. Test: `tar_extract::a_pax_length_past_2_64_takes_the_record_to_the_end`,
   on the reviewer's archive: it extracts `evil`, as Node did. I also checked every other number read from outside:
   - Tar sizes now go through `js_index` (finding 8) instead of `as usize`.
   - Download byte counts are counted by us.
   - GitHub's `size` is a float cast, which saturates.
   - Lock times are bounded by chrono's range.
   - The model catalog sums our own constants.

   None of these can overflow.
3. **Important, model delete reported success.** `delete_whisper_model` removes with `remove_all` and passes on any
   error other than "not there", as `fs.rmSync` threw. Test: `whisper_models::a_model_that_cannot_be_removed_is_an_error`.
   On Windows it holds `model.bin` open without delete sharing. On Unix it uses a read-only folder, and is skipped
   when running as root. The same `let _ =` pattern was also in:
   - `download_file`: an old dest that does not match, and the `.part` of a failed attempt.
   - `acquire_lock`: a stale lock file.
   - The Python download: `.partial`, the old folder, a Python that does not run, and `clean_downloads`.
   - The extractor's cleanup of a half-made folder.

   Each now fails where Node threw.
4. **Important, `permessage-deflate`.** tungstenite 0.30 cannot accept it. It has no extension support and refuses
   any frame with RSV1 set ("Reserved bits are non-zero"). So the offer stays out, and a test now checks that no
   `Sec-WebSocket-Extensions` header is sent. **The live check, run by hand** with the sentence "Hello from Tarsee.
   This is a short test." and the default voice:
   1. I ran the engine as first delivered (node-edge-tts 1.2.10's protocol) through a temporary
      `examples/edge_live.rs`, not committed, using `cargo run --example edge_live -- <out.mp3>`. Result:
      `ERR Unexpected server response: 403`.
   2. I ran Tarsee's own Node library from the main checkout, `node_modules/node-edge-tts` 1.2.10 with
      `ttsPromise`. Result: `NODE ERR Unexpected server response: 403`. The service now refuses 1.2.10's address
      whoever calls it, so **Edge TTS is broken in the Node version too**.
   3. `npm view` lists node-edge-tts 1.2.12 (2026-10-26). Its source moved to
      `wss://api.msedgeservices.com/tts/cognitiveservices/websocket/v1?Ocp-Apim-Subscription-Key=…&Sec-MS-GEC=<v2>&Sec-MS-GEC-Version=2-143.0.3650.75`.
      The new token is a sha256 salted with Microsoft's copyright line plus a 64-bit checksum. Run once by hand
      (from a scratch folder), it returned 17,856 bytes of audio. A second run, to capture its messages, was
      refused by this session's permissions. The messages below therefore come from reading its source, and the
      token values come from the first run.
   4. I ported 1.2.12's protocol:
      - the address and query;
      - the v2 token (`cs64Digest`, with every 32-bit wrap as in the JavaScript);
      - the config message through `JSON.stringify`, and the new SSML indentation;
      - binary frames read by their 2-byte header length;
      - an immediate error when the connection closes before `turn.end`, instead of waiting 10 s;
      - the 10 s limit counting the connection.

      The same example then printed `OK 17856 bytes, audio/mpeg, first bytes ff f3 64 c4, 1647 ms`. That is an MPEG
      audio frame sync, the same size the library gave, with no `permessage-deflate` offered.

   Tests: the 13 Edge tests, rewritten for 1.2.12. The token is checked at five clock values from 1.2.12's
   `generateSecMsGecToken_V2`. They also cover:
   - the exact messages;
   - the close code (1005, and 1006 for a dropped connection);
   - damaged frames;
   - the timeout to connect and the timeout to answer.

   No test uses the network. **This is a deliberate difference from the Node reference, which pins 1.2.10.**
   Bumping `node-edge-tts` to 1.2.12 in `package.json` would make the two agree again, and would make the Node
   version speak again. The lead should decide. Also, the engine's private TLS setup is gone: `wss://` uses the
   process's backend (`net::install_crypto_provider`), and the `webpki-roots` dependency is removed.
5. **Important, Win32 path normalisation on Windows.** The extractor no longer strips the `\\?\` prefix that
   `canonicalize` gives the extraction folder. Every path it writes starts there, so Windows takes `a.`, `b ` and
   `nul` as ordinary names, as Node's `\\?\` paths did. Names are added as plain text (`push_name`), so a link
   target like `a/b:c` is no longer read as a drive. Cleanup also goes through the `\\?\` path. Test:
   `tar_extract::names_windows_would_change_are_written_as_they_are`, with the reviewer's names. It gives 6 files
   and 1 folder, as Node did, and the `a/b:c` link is inside the folder ("a link this computer can't make" here,
   as in Node). Breaking the fix back to plain paths reproduces "names d. as both a file and a folder".
6. **Minor, `PATH` case.** The foundation's `Env` now matches `Path`, which fixes `find_program`. A test runs Piper
   with only `Path` set: `voice::a_program_is_found_on_a_path_spelled_in_any_case`, Windows only. Python's command
   looked `PATH` up in a plain map, so it now looks it up in any case on Windows (`path_variable`).
7. **Minor, empty Location.** An empty Location is no redirect, so the 3xx answer is returned. Test:
   `install_common::a_redirect_with_an_empty_location_is_the_answer_itself`. It gives "huggingface.co answered
   HTTP 302 for x", not "too many redirects".
8. **Minor, negative sizes.** `take`, and `take(padded).subarray(0, size)`, use JavaScript's index rules
   (`js_index`): a negative index counts from the end, NaN is 0, and fractions are cut. The decoder is read in
   zlib's 16 KiB pieces, so what is buffered matches Node. Test: `tar_extract::negative_sizes_are_read_with_javascript_s_index_rules`.
   It checks -1750 (on `x` and `L` headers: nothing extracted), -1, -0 and -777777 (both files extracted), and a
   file with a negative size (damaged), all as Node gave them. In Node, for archives bigger than one 16 KiB piece,
   the outcome depends on zlib's chunking. Here it depends on the same 16 KiB reads, and I did not check further.
9. **Minor, bytes after the gzip data.** `NodeGunzip` follows zlib's rule. After a member, a zero byte ends the
   data (padding), and anything else must be another member. The rest of the stream is read once the archive
   ends, so a damaged end is found as zlib found it. gzip errors use zlib's words for the common cases. Test:
   `tar_extract::what_follows_the_gzip_data_is_read_as_zlib_read_it`, against Node's results:
   - trailing text: "incorrect header check";
   - trailing zeros, and zeros then text: extracted;
   - two members: extracted;
   - an empty file and a cut-off file: "unexpected end of file".
10. **Minor, SIGKILL.** `tts_interface::terminate` sends SIGTERM on Unix and ends the process on Windows, as Node
    did. `exec_file`, `run_python` and whisper's 60 s limit use it. Test: `voice::a_program_out_of_time_is_asked_to_stop`,
    which checks the signal on Unix.
