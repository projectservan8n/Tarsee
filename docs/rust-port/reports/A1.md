# A1: AI provider registry

Ported by the A1 agent on branch `port/A1`. The five files of the package and the key-lookup part of
`src/db/settings.js` (the extra work in the dispatch) are done. The package has 230 tests (registry 98, model refs
15, engine errors 26, key lookup 14, picker 32, catalog 45); the whole suite is 326 passed, 0 failed.

Besides the ported tests, every function was compared with the Node code on the same inputs at development time (a
Node script wrote down what the Node module answered; a temporary Rust test, not committed, ran the same calls; it
was run again on the final code):

| Module | Answers compared | Result |
|---|---|---|
| `provider-registry.js` | 198,213 (25 catalog and settings scenarios, every provider spelling against some seventy model names, plus the table itself) | all the same |
| `engine-errors.js` | 26,083 | all the same |
| `model-picker.js` | 2,051, of which 496 whole picker lists byte for byte (the test catalog, two real Claude Code account catalogs and the catalog inside an installed CLI build, read with `catalog_from_build_text`; read at development time only, nothing of them is in the repository) | all the same |
| `openrouter-catalog.js` | 221 (the recorded list at three dates, about a hundred odd rows one by one, 37 section sets, labels, searches) | all the same, key order included |
| `settings.js` key lookup | 7,589 (a real `SettingsStore` on a scratch database) | all the same |

The comparison found three real differences on the way, all fixed: a number-like key written `1e+21` by JavaScript,
`isEmptySetting` of a lone U+FEFF (JavaScript trims a byte order mark, Rust's `trim` does not), and a major version
too long for a `u64`.

Names and shapes that are not the obvious translation:

**`provider_registry.rs`**

- **`ProviderRegistry` (a service of the `App`) holds what the JS module kept in module-level variables that change:**
  the runtime catalogs and the hidden providers. `ProviderRegistry::of(&app)` gives the app's (made on first use);
  `ProviderRegistry::new()` makes a free-standing one (the unit tests use that, so they need no app). Every JS
  function that read that state is a **method** under its JS name: `hide_providers`, `is_shipped`,
  `shipped_providers`, `active_provider_id`, `set_catalog_models`, `catalog_models`, `models_for`,
  `resolve_model_for`, `context_tokens_for`, `set_local_models`, `efforts_for`, `caps_for`, `price_for`,
  `claude_list_price`. Everything else is a free function: `normalize_provider_id`, `get_provider`,
  `local_ai_hidden_here`, `keys_only_locked`, `keys_only`, `verified_models`, `is_tier_word`, `engine_for`,
  `vendor_for`, `local_context_tokens`, `is_deep_seek_peak`, `check_key_slot`.
- `activeProviderId(store, { env, isShipped })`: `reg.active_provider_id(store, env)`, and the free function
  `active_provider_id_with(store, env, is_shipped)` for the `isShipped` seam.
- **`Engine` is an enum** (`ClaudeCode`, `Codex`; `as_str()`, `from_id()`, serialises as "claude-code"/"codex") and
  so is **`ProviderKind`** (`Subscription`, `Key`, `Local`). `catalog` stays a `&'static str` ("claude", "static",
  "openrouter", "openai-models", "chatgpt-models", "local-models"): it is also the name `set_catalog_models` takes.
- `PROVIDERS` is a `LazyLock<ProviderTable>` with one field per provider (`PROVIDERS.claude.storage_id`), plus
  `PROVIDERS.get(id)` and `PROVIDERS.iter()` (table order). `get_provider()` returns `Option<&'static Provider>`.
- `Provider`: `baseUrl[engine]` is `p.base_url(engine)` (the pairs are `p.base_urls`); `tiers[tier]` is
  `p.tier(tier)` (pairs in `p.tiers`); `keyPattern` is `Option<KeyPattern>` (`is_match`, `as_str`); `wrongSlot` is
  `Vec<&'static WrongSlot>` (`re`, `message`, `matches(key)`); `testProbe`/`balanceProbe` are `Probe` (every field
  optional: `kind`, `check`, `method`, `url`, `path`, `auth`); `errorHints` is `ErrorHints`; `models` is
  `Arc<Vec<ModelEntry>>`; `defaultModel`/`backgroundModel` are plain fields (there is no import cycle to guard
  against any more).
- `AI_PROVIDERS` is a `LazyLock<AiProviders>`: `get(storage_id)`, `iter()`, `keys()`; an entry (`AiProvider`)
  serialises with the JS keys in the JS order.
- A model row (table or runtime catalog) is one struct, `ModelEntry`. Serialised it has the runtime-catalog shape
  (`id, label, vendor, context, efforts, vision, pdf, price, tier, default, free`, `serverContext`/`maxContext` only
  when set). The JS table rows had slightly different key sets (the Claude rows had `tier, alias` and no
  `default, free`); no caller sends a row as it is, they all pick fields.
- Prices: `ModelPrice { input, output, cache_read, cache_write, peak: Option<PeakWindow> }` for a row and
  `Price { input, output, cache_read, cache_write, peak: Option<bool> }` for `price_for`'s answer. `in` is a Rust
  keyword, so the fields are `input`/`output`; they serialise as `in`/`out`. `From<Price> for ModelPrice` exists
  for the picker's wording.
- `set_catalog_models(name, &[Value])` takes the rows as JSON (the JS read them leniently: a context as a string,
  a price as text) and returns `anyhow::Result<()>` where the JS threw for a name that is not a runtime catalog.
  `set_local_models(&[Value], store)` likewise (a row may be a bare id string).
- `local_context_tokens(own: Option<&Value>, server_context: Option<u64>, max_context: Option<u64>)`: `own` is the
  raw setting (number or text), the other two are counts.
- A moment (`priceFor`'s `at`, `isDeepSeekPeak`'s argument) is `Option<i64>`: milliseconds since 1970, `None` for
  now. A caller holding an ISO string passes `util::js::ms_from_iso(text)`; unreadable text gives `None`, which is
  "now", as in the JS.
- `verified_models` returns `serde_json::Map<String, Value>` (the entries are free-form JSON from settings).
- `check_key_slot` returns `KeySlotCheck { ok, message }`; `caps_for` returns `Option<Caps>`.
- `store` is `Option<&dyn Settings>` everywhere the JS had `store = null`.

**`model_ref.rs`**: `parse_model_ref(&str) -> ModelRef { provider: Option<&'static str>, model: Option<String> }`;
`format_model_ref(provider: Option<&str>, model: Option<&str>) -> anyhow::Result<String>`; the object form
`formatModelRef({ provider, model })` is `model_ref.format()`.

**`engine_errors.rs`**: `ErrorKind` is an enum (`as_str()`, `from_name()`, serialises as the JS string);
`ERROR_KINDS: &[ErrorKind]`. `classify_engine_error(provider_id, engine: Option<Engine>, EngineFailure { status,
code, message, model }) -> EngineErrorInfo { kind, provider, engine, status, code, recoverable, state, message }`.
`friendly(provider_id, kind, detail: Option<&str>, model: Option<&str>)`. `provider` in the answer is a `String`
(the JS could give null only for a null id, which a `&str` never is).

**`model_picker.rs`**

- `build_picker(&PickerOptions { catalog: Option<&Value>, known_ids, aliases, source, fetched_at, default_effort })
  -> Picker`. `aliases` is the list of family words (the JS took an object of true values). `Picker`,
  `PickerEntry`, `EffortRow`, `EffortBadge`, `PickerNote` serialise to exactly the JSON the Node version sent, key
  for key (`note` is absent, not null, on every model but Fable).
- `literal_end(text, start) -> Option<usize>`: byte offsets where the JS had UTF-16 offsets, and `None` for -1.
- `js_literal_to_json -> anyhow::Result<String>`; `catalog_from_build_text -> anyhow::Result<Option<BuildCatalog>>`
  (an error where the JS threw).
- `clampEffort(levels, want, fallback)`: `clamp_effort(levels, want)` and `clamp_effort_or(levels, want,
  fallback)`. Levels are `&[impl AsRef<str>]` (the JS also took `{ id }` objects; a caller maps them to ids).
- `price_hint`, `cost_tier` take `Option<&ModelPrice>`; `week_average_factor` takes `Option<&PeakWindow>`.
- `context_label(Option<u64>)`.
- `EFFORT_NAMES` is a list of pairs; `effort_name(id)` is the lookup.
- `match_models(choices, query, prefer_provider)` is generic over a `ModelChoice` trait (`provider()`, `id()`,
  `name()`, `model_ref()`), implemented for `serde_json::Value`; it returns references to the caller's own entries.
- `PickerId.version` is `(f64, u32)`: the major is a double, as `Number()` made it.
- Three helpers that write numbers as JavaScript does live here as `pub(crate)`: `js_to_fixed`,
  `js_to_precision`, `js_number_to_string` (see "Changes needed outside this package").

**`openrouter_catalog.rs`**

- `OpenRouterCatalog` (a service of the `App`, `OpenRouterCatalog::of(&app)`) holds the current list and the fetch
  in progress. Methods under the JS names: `refresh_open_router_catalog(store: Arc<dyn Settings>, opts)` (async),
  `load_open_router_catalog(&dyn Settings)`, `open_router_models()`, `catalog_engines_for(id)`,
  `catalog_model(id)`, `open_router_sections(store, query, models)`, and `reset_for_tests()` /
  `set_models_for_tests(rows)` for the JS `__resetForTests` / `__setModelsForTests` (other packages' tests used
  them).
- `init_open_router_catalog(&app, store: Arc<dyn Settings>, opts) -> CatalogHandle`: `handle.ready().await` is the
  first refresh's result, `handle.stop()` ends the timer (a tokio task). The store is an `Arc` because the timer
  outlives the call.
- `CatalogOptions { url, now, force, cancel, timeout, interval }`. There is no `fetch` option: the request goes
  through `app.fetch()`.
- `parse_open_router_models(&Value, now_ms) -> Result<Vec<CatalogModel>, CatalogError>`.
- Rows are typed: `CatalogModel` (serialises to the cached row, same keys and order), `Reasoning`, `PickerRow`,
  `VerifiedSummary`, `Section`. `RefreshResult.source` is the enum `CatalogSource` (`as_str()`).
- The dispatch said the cached copy is "on disk under the app's own folders": in the Node code it is the
  `cache.openrouter.models` **setting**, and that is what is ported (so the two versions read each other's cache).

**`db/settings.rs`** (below the trait): `is_empty_setting(Option<&Value>)`, `is_ai_key_slot(&str)`,
`clean_key(&str) -> Option<String>`, `key_place(&str) -> KeyPlace { slot, env_name, keyless }`,
`key_hint(&str) -> Option<String>`, `get_key_with_source(&dyn Settings, &Env, provider_id) -> KeyWithSource { key,
source, hint }`, `get_key_with_source_from(settings, env, provider_id, env_name: Option<&str>)` for the JS
`{ envName }` option (a name: that variable and no other; `None`: Settings only), `get_api_key(settings, env,
provider_id) -> Option<String>`. `KeyWithSource`'s `Debug` never prints the key. The functions use no constants of
the JS file (the placeholder and Voice-key constants belong to the fixups, which are S1's).

## Differences from the Node behaviour

None in what a person or another program sees on real inputs. The ones below are on inputs that do not occur, or
are wording inside an error's brackets:

1. **OpenRouter list, when the host cannot be reached:** the reason in brackets was Node's own error code
   (`ECONNREFUSED`, `ENOTFOUND`, ...). The Rust client gives no such codes, so refused, DNS, reset and timed-out
   connections are named with the same codes by reading the cause, and anything else shows the cause's own words.
   A body that stops arriving mid-way says the Rust client's words inside "Tarsee couldn't read OpenRouter's model
   list (...)" where Node's said its own.
2. **A cached OpenRouter row whose fields have the wrong type** (a hand-edited setting) is skipped; the JS kept
   whatever was there. Rows either version writes are read back whole.
3. **Claude Code's catalog, a name that is not text** (a number where `name`, `description` or a badge message
   should be): written as text; the JS passed the raw value through.
4. **JavaScript object quirks are not reproduced:** an id or error code spelled like an `Object.prototype` member
   ("constructor") found that member in the JS lookups (`CODE_KINDS[c]`, `verifiedModels(...)[id]`); and an
   object's all-digit keys came first in `Object.entries` (a verified model whose id is only digits).
5. **Dates only as Tarsee writes them:** `issued_at` in a CLI build and `fetchedAt` in the cache are read by
   `util::js::ms_from_iso` (ISO forms). `Date.parse` also took forms like "Oct 23 2026"; neither writer uses them.
6. `set_catalog_models` with an unknown name returns an error (same words) where the JS threw.

## Looks like a bug in the Node code

Ported as it is in each case.

- `openrouter-catalog.js` `getJson`: when the caller's own `signal` stops the request, the reason shown is "20"
  (`err.code` of the abort, the legacy `ABORT_ERR` number): "Tarsee couldn't reach OpenRouter for its model list
  (20)." No caller passes a signal today.
- `openrouter-catalog.js` `usd()`: a price that is not a finite number is "?" without the dollar sign ("? in, $1
  out per million tokens").
- `openrouter-catalog.js` `perMillion`: a per-token price so large that a million of it overflows ("1e300") gives
  a price of Infinity, which the cache then stores as null.
- `openrouter-catalog.js` `dateOnly`: any month takes a day up to 31 ("2027-02-31" is read as 3 March), because
  `Date.parse` rolls the days over.
- `provider-registry.js` `contextTokensFor` on the Claude providers looks the model up exactly as given, so
  "haiku[1m]" or " haiku " counts as an unknown id (1M) though Haiku's window is 200K.
- `provider-registry.js` `claudeListPrice("claude-haiku-4-5-20251001")`: the dated id becomes the slug
  "anthropic/claude-haiku-4-5.20251001" (the pattern takes the last two numbers), which is never listed, so it
  falls through to the family's newest. Harmless, but not what the comment says.
- `model-picker.js` `clampEffort`'s third argument (`fallback`) is passed by no caller.
- `engine-errors.js` `classifyEngineError`: the condition `byStatus && !(kind && !st)` can never be false in its
  second half (a status is needed for `byStatus` to exist).

## Changes needed outside this package

1. **`tokio`'s `test-util` feature is not enabled**, so `#[tokio::test(start_paused = true)]`, which DESIGN.md
   prescribes for timers, does not compile. The catalog's timer tests wait on the requests themselves instead (a
   gate in front of the stubbed client) and assert a lower bound on real time; they take about 0.4 s. A
   `[dev-dependencies] tokio = { version = "1.54.1", features = ["test-util"] }` line would make paused time
   available to every package. I did not add it: it rebuilds tokio and everything on it once for tests, and it is
   a change to an existing dependency, not a new one.
2. **`util::js::number_to_string` is not `String(number)` at the edges:** it writes 1e21 as
   "1000000000000000000000" (JavaScript: "1e+21") and 1e-7 as "0.0000001" ("1e-7"). `model_picker.rs` has exact
   versions (`js_number_to_string`, and `js_to_fixed` / `js_to_precision`, whose ties go up where Rust's
   formatting rounds to even: `(1.25).toFixed(1)` is "1.3", `format!("{:.1}", 1.25)` is "1.2"). They are
   `pub(crate)` there and used by `db/settings.rs` and `openrouter_catalog.rs`; they belong in `util::js`.
3. **`str::trim` is not JavaScript's `trim`** (Rust leaves U+FEFF, a byte order mark that can ride in front of a
   pasted key, and removes U+0085; JavaScript does the opposite). This package never calls `str::trim`:
   `provider_registry.rs` has the local equivalents `js_trim` and `is_js_space` (`pub(crate)`), and every place the
   Node code trimmed a key, a provider or model name, a setting or an API answer uses them (`clean_key`,
   `check_key_slot`, `normalize_provider_id`, `resolve_model_for` and the rest; the environment variables this
   package reads are trimmed the same way, not through `Env::trimmed`). The lead says `util::js::trim` and
   `is_whitespace` now exist on `rust-rewrite`: **switch `js_trim` / `is_js_space` to them at merge** (two
   definitions in `provider_registry.rs`; the callers import them from there). Regular expressions here spell out
   JavaScript's `\s` as a class (`JS_SPACE` in the registry, `S` in engine errors) for the same reason. One place
   still reaches `str::trim`: `config::constants::tier_of` and `resolve_model_alias` (foundation), which this
   package calls with text it has already trimmed.
   **Case-insensitive patterns** are all `(?i-u)` (the wrong-slot key shapes, every engine-error pattern) or
   `eq_ignore_ascii_case`, so the long s or the Kelvin sign cannot pass as an ASCII letter; `to_lowercase()` is used
   only where the Node code called `toLowerCase()`, which folds the same characters.
4. **`serde_json` parses long decimals one unit in the last place off** (numbers of more than about 15 significant
   digits) unless its `float_roundtrip` feature is on. It showed up when a Node-written "1.9285714285714286" came
   back as ...88. Prices and contexts are short numbers and are not affected; a setting holding a long float would
   be. Worth turning the feature on for the port.
5. **The Rust tests read `test/fixtures/openrouter-models.json`** (`include_str!` in
   `src/lib/openrouter_catalog/tests.rs`). When the Node tree is removed that fixture has to move with the tests.
6. **For A3 (session handles):** `vendor_for` is here; for S1: `SettingsStore::get_key_with_source` and friends
   should call the free functions in `db/settings.rs`, and `clearKey` deletes `key_place(id).slot`.
7. **For A2 (`engine_env::ProviderEntry`):** everything `ai/engine-env.js` reads from a registry entry is public on
   `provider_registry::Provider` (`get_provider(id)` or `PROVIDERS.<id>` gives a `&'static Provider`):

   | `engine-env.js` reads | On `Provider` |
   |---|---|
   | `entry.id` | `id: &'static str` |
   | `entry.label` | `label: &'static str` |
   | `entry.envKey` | `env_key: Option<&'static str>` |
   | `entry.engines`, `entry.engines.includes(engine)` | `engines: &'static [Engine]` |
   | `entry.baseUrl?.[engine]` | `base_url(engine) -> Option<&'static str>` (the pairs: `base_urls: &'static [(Engine, &'static str)]`) |
   | `entry.models?.find((m) => m.id === id)?.context` | `models: Arc<Vec<ModelEntry>>`, with `id: String` and `context: Option<u64>` |
   | `entry.tiers` | `tiers: &'static [(&'static str, &'static str)]` (one tier: `tier(name) -> Option<&'static str>`) |
   | `entry.defaultModel` | `default_model: Option<&'static str>` |
   | `entry.wrongSlot[]` (`slot.re.test(k)`, `slot.message`) | `wrong_slot: Vec<&'static WrongSlot>`, with `re: regex::Regex`, `message: &'static str` and `matches(key) -> bool` |

   `engine-env.js` imports nothing else from the registry (it takes the entry as an argument). The engine is the
   enum `Engine` here; if A2 holds engines as text, `Engine::from_id` / `as_str` convert.

## Risks

What a reviewer should look at first:

1. **The shape of the registry's API** (methods on `ProviderRegistry` for what reads the runtime lists, free
   functions for the rest; `Engine`, `ProviderKind`, `ErrorKind` as enums; typed rows). Every later AI package
   calls it, so a change of mind here is cheapest now.
2. **`refresh_open_router_catalog`'s shared fetch** (`futures::Shared` kept in the service until it finishes). If
   every caller of an unfinished fetch is dropped (the timer stopped mid-request), the unfinished fetch stays and
   the next caller resumes it; it holds an `Arc` of the service until then.
3. **`model_picker::js_literal_to_json`** walks UTF-16 units to keep the JS error positions; it was checked on the
   real CLI build's catalog, but it is the most hand-written parser in the package.
4. **The catalog's timer tests use real time** (see 1 above): the lower bound cannot flake, but they are the only
   tests here that take hundreds of milliseconds.
5. `ModelEntry`'s JSON has one shape for all rows; if a later package does send table rows to the browser as they
   are, the Claude rows' keys differ from the JS (see Files).
