## Differences from the Node behaviour

1. **JavaScript hooks and plugins are not run** (DESIGN decision 5): each `workspace/hooks/*.js` and `workspace/plugins/*/index.js` is logged and listed. Workspace hooks are now programs with a JSON manifest (`docs/hooks.md`).
2. **The service runs `tarsee start`** (the current executable) instead of `node src/server.js`.
3. **Interactive chat handles lines one at a time.** Node handled each line as it arrived, so with piped input a `/quit` could end the process before a reply came. Ctrl+C prints `Goodbye!` (readline did the same through `close`).
4. **Text of OS and JSON errors.** Where an `err.message` reached a response or log (`POST /api/skills/install` 400, the skills routes' 500s, `[workspace] could not update`, `[checkpoint] ...`), Rust's `io::Error` text replaces Node's (`No such file or directory (os error 2)` for `ENOENT: no such file or directory, open '...'`). A request body that is not JSON gets serde's message instead of V8's.
5. **Directory order is Node-on-Linux's everywhere** (sorted by name, byte by byte, as libuv sorts). Node on Windows listed in NTFS order.
6. **`is_running`** uses the shell's `kill -0` (Unix) and `tasklist` (Windows) instead of `process.kill(pid, 0)`; a negative id is "not running" (Node checked a process group).
7. **Canvas answers**: no ETag on the pages sent as text (the gallery, the sign-in page, `Forbidden`, `Canvas not found`: Express hashed each body with SHA-1, which is not among the dependencies); a canvas file's own ETag, Last-Modified, ranges and conditional answers come from tower-http plus the weak ETag the send module made. The send module percent-decoded the path after the existence check; here the path stays as sent (only matters for a folder whose name holds `%xx`).
8. **Hook timeout stops the handler.** Node's `Promise.race` left a timed-out handler running in the background; here it is dropped (a program hook's process is killed). A handler with no result gives `result: null` where Node left it undefined (nothing reads it).
9. **`POST /api/memory`** with a non-text `category` stores and answers it as text (`"5"`); Node answered the number it was given. A repeated query parameter (`?category=a&category=b`) reads as `"a,b"`; Node handed an array to SQLite and answered 500.
10. **Agent registry**: a missing `prompt` prints as `undefined` in the summary and a non-text nickname never matches, where Node threw a TypeError.
11. **Diagram node ids** `1` and `1.0` (as JSON) are different nodes; JavaScript treats them as one.

## Looks like a bug in the Node code (ported as it is)

1. **Skill names are paths.** `POST /api/skills/install|uninstall` and `/setup` join the name to the skills folders without checking it: `../x` copies or removes folders outside them, and `/setup` with `""` copies every shipped skill into the root of `workspace/skills`. (Signed-in owner only.)
2. **`PUT /api/skills/:name` that keeps the content adds a blank line** to the top of the body each time (the body read back keeps the newline after the frontmatter, and the write adds another).
3. **Only `boot:ready` is ever emitted**, so the built-in `command-logger` and `session-memory` hooks never run, and a workspace hook on any other event never fires. `docs/hooks.md` says so.
4. **Canvas gallery links to names that need encoding do not work**: the link percent-encodes the folder name, the middleware looks the encoded name up as it is. The `startsWith(CANVAS_DIR)` check also lets `..` reach a sibling folder whose name starts with `canvas` (e.g. `workspace/canvas-old`).
5. `initAgentRegistry` seeds the defaults only when an empty list is stored (with nothing stored, `getAgents` already returns the defaults, so nothing is ever written). Harmless.
6. The boot context summary says `restarted NaNh ago` for an unreadable `savedAt`, and shows a conversation with no `updatedAt` as `Invalid Date` instead of skipping it.
7. The systemd unit's `ExecStart` does not quote the program path (a path with a space breaks).
8. Memory search: SQLite's `LOWER()` is ASCII-only, so a non-ASCII word in another case is never found, although the scoring lower-cases fully. A negative `?limit=` becomes `LIMIT -n`, which is no limit.

## Risks

1. **Not run on Linux.** Unix-only branches: `is_running` (`/bin/sh -c "kill -0 <pid>"`), program hooks (`.sh` scripts, `kill_on_drop`), the gallery test with a `<img src=x>` folder name, path normalisation in the canvas middleware. CI on Linux should be the first check.
2. **Local times follow the process's zone** (`TZ`, else the system's), as Node's `toLocaleTimeString` did, not `TARSEE_TIMEZONE`: the daily log's `[HH:MM:SS]`, the boot context's `h:mm:ss AM`, the gallery's `M/D/YYYY`. On Railway (no `TZ`) that is UTC, as before.
3. **Program hooks**: a timed-out program is killed, but not its own children (a shell script's `sleep` survives). Command resolution (beside the manifest, then the workspace, then PATH) is new; see `docs/hooks.md`.
4. **Canvas file serving** through `ServeFile`: content types are mapped by hand for the common extensions to match mime-types (`text/javascript; charset=utf-8`, `image/vnd.microsoft.icon`), `mime_guess` for the rest. A reviewer should look at `send_file` first.
5. **`express_json_body`** emulates body-parser 2 (JSON only for `application/json`, empty body is `{}`, objects and arrays only); `axum::Json` is not used in these two routers because its rejections differ from Express's.
