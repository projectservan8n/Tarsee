## Differences from the Node behaviour

1. **JavaScript hooks and plugins are not run** (DESIGN decision 5): each `workspace/hooks/*.js` and `workspace/plugins/*/index.js` is logged and listed. Workspace hooks are now programs with a JSON manifest (`docs/hooks.md`).
2. **The service runs `tarsee start`** (the current executable) instead of `node src/server.js`.
3. **Interactive chat handles lines one at a time.** Node handled each line as it arrived, so with piped input a `/quit` could end the process before a reply came. Ctrl+C prints `Goodbye!` (readline did the same through `close`).
4. **Text of some OS and JSON errors.** The skills routes' file errors now carry Node's text (`EACCES: permission denied, mkdir '...'`, through `lib::safe_path::fs_error_message`); the log lines `[workspace] could not update ...` and `[checkpoint] ...` still carry Rust's `io::Error` text. A request body that is not JSON gets serde's message instead of V8's. The `[error]` line of an unhandled 500 has the error's class and message but not Node's stack trace (those were the Node program's own lines).
5. **Directory order is Node-on-Linux's everywhere** (sorted by name, byte by byte, as libuv sorts). Node on Windows listed in NTFS order.
6. **`is_running`** uses the shell's `kill -0` (Unix) and `tasklist` (Windows) instead of `process.kill(pid, 0)`, with the app's environment; a negative id is "not running" (Node checked a process group).
7. **Canvas content types** for extensions outside the common list come from `mime_guess`, which may name a type differently from mime-types (the common ones are mapped by hand to mime-types' answers).
8. **Hook timeout stops the handler.** Node's `Promise.race` left a timed-out handler running in the background; here it is dropped (a program hook's process is killed). A handler with no result gives `result: null` where Node left it undefined (nothing reads it).
9. **`POST /api/memory`**: values that are not text are bound as better-sqlite3 bound them (a number is stored as `"5.0"` and answered as sent; `true`, an object, an array of two or more, a nested array are the same 500s with the same messages). Remaining difference: none known.
10. **Agent registry**: a missing `prompt` prints as `undefined` in the summary and a non-text nickname never matches, where Node threw a TypeError.
11. **Diagram node ids** `1` and `1.0` (as JSON) are different nodes; JavaScript treats them as one.
12. **Express's ETag on JSON answers.** Express put a weak ETag on every `res.json`/`res.send` body and answered 304 to a fresh GET. The canvas pages do this now; the JSON of the skills and memory routes does not (a server-wide concern: see "Changes needed outside").
13. **Node bugs fixed, by the owner's rule** (anything that can destroy data or weakens a security check):
    - A skill name in install, uninstall, setup, update and delete must be one plain name (no separators, not `.` or `..`, not absolute, not empty); any other is answered as a skill that does not exist. Node joined it (`../x` left the skills folders, `/setup` with `""` copied every shipped skill into the root of `workspace/skills`).
    - `PUT /api/skills/:name` that keeps the content no longer adds a blank line to its top each time.
    - The canvas middleware compares the file's path with the canvas folder as paths, so `..` no longer reaches a sibling folder whose name starts with `canvas` (`/canvas/../canvas-old/x` is 403).
    - A canvas id, an agent id (for its folder) and a workspace file name cannot lead out of their folder (Node's `path.join` followed `..`).

## Looks like a bug in the Node code (ported as it is)

1. **Only `boot:ready` is ever emitted**, so the built-in `command-logger` and `session-memory` hooks never run, and a workspace hook on any other event never fires. `docs/hooks.md` says so.
2. **Canvas gallery links to names that need encoding do not work**: the link percent-encodes the folder name, the middleware looks the encoded name up as it is (a canvas folder named `my canvas` is listed and answers "Canvas not found"; one named `a%20b` is served at `/canvas/a%20b/`).
3. **No canvas file is served under a dotted folder.** The send module refuses a path with any part that starts with a dot, the parts above the workspace included, so with the default local state folder `~/.tarsee` every canvas file answers 404 (the gallery still lists them). On Railway (`/data/tarsee`) this does not arise.
4. `initAgentRegistry` seeds the defaults only when an empty list is stored (with nothing stored, `getAgents` already returns the defaults, so nothing is ever written). Harmless.
5. The boot context summary says `restarted NaNh ago` for an unreadable `savedAt`, and shows a conversation with no `updatedAt` as `Invalid Date` instead of skipping it.
6. The systemd unit's `ExecStart` does not quote the program path (a path with a space breaks).
7. Memory search: SQLite's `LOWER()` is ASCII-only, so a non-ASCII word in another case is never found, although the scoring lower-cases fully. A negative `?limit=` on the list becomes `LIMIT -n`, which is no limit; on the search it is `slice(0, -n)`, which leaves the last n results off.
8. An agent whose id is not text stops the server's start (`initAgentRegistry` throws outside any `try`).

The capturing logger becomes the logger of the test binary on first use; nothing else in the tests installs one today. If another package adds its own test logger, only one can be installed.
2. **`tests/it/main.rs`**: `mod daemon;` and `mod hooks;`. **`testbin/main.rs`**: the role `sleeper`.

Several packages need the same.
4. **`util::node_path::normalize`** pushes each part onto a `PathBuf`, so on Windows a part such as `C:` in the middle of a path replaces what came before. The canvas middleware uses `lib::safe_path::join_path`/`normalize_path` (B2), which build the path as text and do not have this.
5. **A4**: `routes::skills::unhandled_error` reproduces the global error handler's 500 body (`{ error: "Internal server error", detail }`, no detail in production) for the few errors the Node routes did not catch; it does not call self-heal's `recordError`. Once A4 lands, Z1 or A4 may want these to go through it.
6. **Z1**: Express's ETag and 304 on every JSON answer (difference 12), and what an unmatched method answers (fix round 1, finding 10), are server-wide; `server.rs` is the place for both.
7. **Callers** (S1 build-system-prompt, S3 tools, S5 heartbeat/boot-runner/subagents, K1 commands, Z1 server): the shapes above. Z1's boot needs `upgrade_default_workspace_files(&app, None)`, `init_agent_registry` (its error stopped the Node server), `MemoryStore::sync_to_memory_file`, the default skills install (`scan_skills` + `install_skill`), `save_boot_context` every 5 minutes and at shutdown, `load_hooks` (then `[tarsee] hooks loaded: <n>`), `load_plugins`, `HookRegistry::of(&app).emit("boot:ready", json!({}))` after 2 s, `write_pid`/`remove_pid`, and `canvas_middleware` layered after `session_auth`.

## Risks

1. **Not run on Linux.** Unix-only branches: `is_running` (`/bin/sh -c "kill -0 <pid>"`), program hooks (`.sh` scripts, `kill_on_drop` and the reaping of the killed program), the gallery test with a `<img src=x>` folder name, an absolute workspace file name that stays under the workspace. CI on Linux should be the first check.
2. **Local times follow the process's zone** (`TZ`, else the system's), as Node's `toLocaleTimeString` did, not `TARSEE_TIMEZONE`: the daily log's `[HH:MM:SS]`, the boot context's `h:mm:ss AM`, the gallery's `M/D/YYYY`. On Railway (no `TZ`) that is UTC, as before. The locale is always US English (fix round 1, finding 25).
3. **Program hooks**: a timed-out program is killed, but not its own children (a shell script's `sleep` survives). Command resolution (beside the manifest, then the workspace, then PATH) is new; see `docs/hooks.md`.
4. **Canvas file serving** is now this package's own code (`send_file`): conditional requests (fresh 2.0.0), preconditions, ranges (range-parser 1.2 with `combine`), HEAD, streaming from an offset. A reviewer should look at it first.
5. **`express_json_body`** emulates body-parser 2 (JSON only for `application/json`, empty body is `{}`, objects and arrays only); `axum::Json` is not used in these two routers because its rejections differ from Express's.
