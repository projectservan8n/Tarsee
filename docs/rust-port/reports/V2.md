Module state is app services, as DESIGN says: `PhononWorker` (the warm worker), the `import ptts` cache, `TtsRegistry`
(the engine in use and the init counter), `SttInstall` (runtime found, job, last results, the tests' catalog),
`SttWorker`, `SttTestOverrides`, `PhononInstaller` (the run, its progress, the one boot attempt). Each worker process is
held by a handle whose drop kills it, so stopping a worker or dropping the app ends the process (tested with a stand-in
that would otherwise keep running).

Names and shapes that are not the obvious translation:

- **Workers.** `PhononWorker::of(app)`, `synth(app, req) -> Result<Value, String>`, `start`, `stop`, `is_ready`,
  `device`; `stop_phonon_worker(app)` removes it from the app and stops it. `SttWorker::of(app).transcribe(app, rt, req,
  timeout)`; `stop_stt_worker(app)`. The plumbing both share (a settle-once promise, an incremental UTF-8 decoder, a
  watched child process) is `phonon_engine::line_worker` (crate-private).
- **`phononPaths()`** is `phonon_paths(&App) -> PhononPaths` (`python` is a `String`: a path or "python3");
  `phononInstalled(p)` is `phonon_installed(&PhononPaths)`; `canImportPtts(python)` is `can_import_ptts(&App, &str)`;
  `resetPhononAvailability()` is `reset_phonon_availability(&App)`; `phononThreads()` is `phonon_threads(&Env)`.
- **`clampSpeed(x)`** is `clamp_speed(f64)` plus `clamp_speed_value(&Value)` (JavaScript's `Number()` of a setting);
  `findVoice(x)` is `find_voice(&str)` plus `find_voice_value(Option<&Value>)`. `VOICES` is `&[PhononVoice { id, name }]`.
- **`new PhononTTSEngine(voice, { barePeso })`** is `PhononTtsEngine::new(&App, Option<&str>, PhononOptions)`; it keeps a
  `WeakApp`.
- **Engine registry.** `getTTSEngine()`/`setTTSEngine(e)`/`stopTTSEngine()` take `&App`. `initTTSEngine(store, {
  loaders })` is `init_tts_engine(&App, Option<Arc<dyn Settings>>, InitOptions { loaders: HashMap<String,
  EngineLoader> })`. `FallbackTTSEngine` is `FallbackTtsEngine` (`FAILS_TO_TRIP`, `TRIP`; the pause runs on tokio's
  clock so a test can let it pass). New: `can_warm(engine)` (see differences).
- **`getApiKey(id)`.** The settings store's method is not ported yet (A1 ports the key lookups, S1 the store). V2 needs
  it for two ids only, `openai` and `elevenlabs`, whose places the Node `keyPlace` gives without the provider registry
  (`ai.<id>.apiKey`, then `<ID>_API_KEY`, quotes and spaces trimmed): `engine_registry::api_key(settings, env, id)`
  does exactly that. It should be replaced by A1's function when A1 is merged.
- **`cloneVoice(buf, name, db)`** is `clone_voice(&App, &[u8], &str) -> Result<ClonedVoice, TtsError>`;
  `listVoiceProfiles(db)` is `list_voice_profiles(&Db) -> Vec<VoiceProfile>`.
- **stt-install.** `findSttRuntime({ refresh })` is `find_stt_runtime(&App, bool) -> SttRuntime` (`Ready(ReadyRuntime)`
  or `NotReady { base, custom, problem }`), shared by concurrent callers (a `tokio::sync::OnceCell`, not a stored
  future, so nothing holds the app). `resolveSttModel(want)` is `resolve_stt_model(&App, &str) -> ResolvedModel`
  (`Found { model, wanted }` or `Missing(name)`). `chosenModel(store)`, `findSttModel(name)` take the app (the tests'
  catalog is per app). `startSttInstall(opts)` / `startModelDownload(name, opts)` give `Result<StartedJob { job:
  JobSnapshot, done: JobDone }, SttJobError { message, code, status }>`; `done.wait()` is the never-failing `done`
  promise. `getSttStatus({ refresh, settingsStore })` is `get_stt_status(&App, bool, Option<&dyn Settings>) ->
  SttStatus` (serializes to the JS object, field for field). `__setForTests({ catalog })` is `set_for_tests(&App,
  Option<Vec<WhisperModel>>)`; `__resetJobsForTests()` is `reset_jobs_for_tests(&App)`. `modelFailedRecently(name,
  ms)` is `model_failed_recently(&App, &str, Duration)` (`MODEL_RETRY_PAUSE` is the default).
- **stt-handler.** `transcribeAudio(buf, language, { settingsStore })` is `transcribe_audio(&App, &[u8],
  Option<&str>, Option<&dyn Settings>) -> Result<SttResult, SttError>`; `SttError { message, status, code }` keeps
  "stt-unavailable"/"stt-failed" for the channels. `warmSTT(store)` gives the JSON `Value` it gave. `__setForTests({
  local, timeoutMs, idleMs })` is `set_for_tests(&App, SttTestOverrides { local: Option<LocalTranscriber>, timeout_ms,
  idle_ms })`; `LocalTranscriber { available, transcribe }` are boxed async closures (`LocalTranscriber::available(b)`
  and `.answering(result)` build the common ones). The channel packages (H1, H2) and S1's `stt-opt-in` port use this.
- **phonon-install.** `installPhonon(opts)` is `install_phonon(&App, InstallOptions) -> InstallRun`, a
  `futures::future::Shared` future: concurrent calls get the same one (`Shared::ptr_eq` is the JS `a === b`). The
  install runs in a task whether or not anyone awaits it, as a JS promise did. `opts.ensureRuntime` / `opts.smokeTest`
  / `opts.onInstalled` / `opts.onProgress` are `Arc` closures. `autoInstallPhonon(store, { install, onInstalled,
  delayMs })` is `auto_install_phonon(&App, Option<&dyn Settings>, AutoInstallOptions)`. `downloadFile` and
  `acquireLock` are re-exported as in Node. The terminal entry (`node src/voice/phonon-install.js`) is
  `run_install_command(&App) -> i32`.
- **Routes.** `voiceRouter` is `routes::voice::router()`; `createSttRouter({ limits })` is `create_stt_router(Limits {
  max, window })`. The settings store is read from the app as the service `Arc<dyn Settings>`
  (`routes::voice::settings_store`), the Node `req.app.get("settingsStore")`.
- **Doctor.** `runDoctor()` is `run_doctor(&App, &mut dyn Write)`; `doctor_checks(&App) -> Vec<Check>` and
  `format_report(&[Check]) -> String` are separate so the report can be tested. Checks that changed (as the dispatch
  asked): **"Node.js"** (Node 18 or newer) became **"Tarsee"**: `v<version> (<platform> <arch>)`, always a pass (there is
  no separate runtime). **"Playwright"** (the npm package loads) became **"Browser"**: pass with the path of a browser
  found by `doctor::find_browser`: TARSEE_CHROMIUM_PATH (when the file is there), then Playwright's download
  (PLAYWRIGHT_BROWSERS_PATH, else its default cache folder; newest `chromium-*` build), then `chromium`, `google-chrome`,
  `chrome`, `msedge`, ... on the PATH, then the usual install folders on Windows and macOS; else a warning "No
  Chromium, Chrome or Edge found (browser tool unavailable; set TARSEE_CHROMIUM_PATH)". **"SQLite"** ("better-sqlite3
  loaded") reads "SQLite <version> (built in)". ffmpeg, speech-to-text, memory (`os.freemem()`: MemAvailable on Linux,
  `vm.page_free_count` on macOS, `GlobalMemoryStatusEx` on Windows) and the two environment checks are as in Node, as
  is the output format.

## Differences from the Node behaviour

- **`DELETE /api/voice/piper-voices/:id`** refuses an id that is not one plain name (empty, `.`, `..`, a separator, a
  drive, absolute) with 400 `{ "error": "Invalid voice id" }`. Node joined the id unchecked (V1 listed the bug), and
  Rust's `join` is worse: an absolute id would replace the folder entirely. Ids Tarsee makes are always plain names.
- **`POST /api/voice/warm`** decided "has a worker to warm" by `typeof engine.warm === "function"`, true only for Phonon
  and its Edge-backed wrapper. The `TtsEngine` trait gives every engine `warm`, so it is decided by the engine's name
  ("phonon"): `engine_registry::can_warm`. A test engine called "phonon" without a worker now reads as warmable.
- **Stopping a worker** kills it (SIGKILL on Unix); Node sent SIGTERM. Neither Python worker handles SIGTERM.
- **Output of an old worker** (one already stopped or replaced) is ignored. Node's Phonon worker processed every
  process's stdout, so a late "ready" from a stopped process could mark the new one ready.
- **The STT worker's stderr** is read to its end before its exit is reported, so the error carries the worker's last
  line even when the exit event came first in Node.
- **Upload errors** from a malformed multipart body are axum's (multer's) texts, not busboy's ("Unexpected end of
  form"). A missing or non-form content type, and a missing boundary, keep busboy's words.
- **Response headers**: Express added a weak `ETag` to every `res.send`/`res.json` answer; no route ported so far adds
  one (a server-wide matter for Z1).
- **`/api/voice/stt/install`'s and `.../download`'s first snapshot** is made by running the job's first update before
  answering, which is what Node's synchronous prefix did; the rest of the job runs on a task.

## Looks like a bug in the Node code (ported as it is)

- `routes/voice.js` `deletePiperVoice(req.params.id)`: path traversal (fixed here, see above).
- `routes/voice.js` `/tts-stream` answers 500 for every engine error, even a 400 or 501 the engine gave (`/tts` keeps
  the engine's status). With the stub engine it answers 500 "TTS engine not configured...".
- `stt-handler.js`: `modelBytes(model.missing)` uses the real catalog, not the one in use, so with a test catalog the
  size in "downloading base.en (148 MB)" is the real size; with a model name only the test catalog has it would throw.
- `stt-handler.js`: a worker that answers `{ ready: false }` and stays alive keeps its process: every later
  transcription fails at once with the same error until the worker exits or is stopped.
- `phonon-engine.js` `_onStdout`: a second `{ ready: true }` while ready is taken as the answer to the request in
  flight (and fails it with "phonon worker error").
- `engine-registry.js`: `"auto"` and the fallback order never reach the stub while Edge TTS can be built, so the
  `/tts` route's 501 "No TTS engine available" is practically unreachable.
- `stt-install.js` `listSttModels`: a job's `percent` can become NaN (shown as null) if a catalog lists a model of 0
  bytes.

## Changes needed outside this package

- **The settings store in the app.** The routes read it as the app service `Arc<dyn Settings>`
  (`app.set::<Arc<dyn Settings>>(store)`). S1/Z1 should store it that way at boot, or change
  `routes::voice::settings_store` (one function) to however S1 exposes it.
- **`getApiKey`**: replace `engine_registry::api_key` with A1's key lookup when A1 is merged (same answers for the
  two ids used).
- **Z1**: mount `routes::voice::router()` at `/api/voice` behind `requireAuth` and `csrfProtect`; at boot call
  `init_tts_engine(app, Some(store), Default::default())`, `auto_install_phonon(app, Some(&*store), AutoInstallOptions {
  on_installed: Some(<init_tts_engine again>), ..Default::default() })` and log `stt_boot_line`; at shutdown
  `stop_tts_engine(app)` and `stop_stt_worker(app)`. CLI: `tarsee doctor` is `run_doctor(&app, &mut stdout)`, and
  `tarsee phonon-install` (the Node `node src/voice/phonon-install.js`) is `run_install_command(&app)`, with logging set
  up so the `[phonon]` lines reach the terminal.
- **The two stt-routes cases** that test sign-in, CSRF and the API token in front of `/api/voice` are for B1 or Z1.
- **`util::js::trim`** is on `rust-rewrite` after this branch was cut; V2 uses V1's `speech_text::js_trim`, the same
  JavaScript whitespace set, everywhere it trims text from outside. Switch at merge if wanted.
- **V1's `PATH` lookup** (`find_program`, and `python_command`'s `which_in(.., env.get("PATH"))`) is case-sensitive,
  which misses Windows' `Path`. V2's own lookups (the doctor's ffmpeg and browser) are case-insensitive on Windows. The
  two Python workers and the `import ptts` check start Python through V1's `python_command`, so on Windows a bare
  "python3" relies on its fallback (the OS search) until V1's fix lands. No V2 test depends on that lookup (they use
  absolute paths or the fake Python's hook).
- The browser lookup in `cli::doctor::find_browser` is what the browser tool's package will need too; it can move there.

## Risks

- **Unix code not compiled here** (Windows only): `line_worker`'s `ExitStatusExt::signal`, the doctor's
  `free_memory` for Linux and macOS (`sysctlbyname`), the `kill -0` liveness check in `tests/it/tts_phonon.rs`, and the
  Unix branches of the tests' paths. Written with care; the first Linux run compiles them. Look at
  `cli/doctor.rs::free_memory_impl` first.
- **The two worker state machines** (`PhononWorker`, `SttWorker`) are hand-written equivalents of the JS event
  handlers. Look at the order of settling the ready promise, failing the request in flight and dropping the process in
  `exited`/`exit`/`stop_locked`, and at the timeouts: the 30 s Phonon synth timeout and the 120 s / 90 s boot timeouts
  are not exercised (the Node tests had no seam for them either); the STT request timeout is (400 ms).
- **Settings in routes**: until the store is in the app, every route behaves as Node did with no store (defaults, and
  500 for `POST /stt-model`).
- **ETag** missing from answers (above) is the one header difference a client could notice.
