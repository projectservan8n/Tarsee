Names and shapes that are not the obvious translation:

- **Everything that read the module-level config or state takes `&App` first**: `vault::encrypt(app, text)`,
  `key_vault::set_key(app, ...)`, `auth::create_session(app, ip)`, `auth::validate_password(app, text)`, and so on.
- **`vault`**: `decrypt`, `decrypt_if_encrypted` and `decrypt_secret_fields` return `Result<_, VaultError>`; the
  error's text is the Node message. `is_encrypted` takes `&str` (for a JSON value:
  `value.as_str().is_some_and(is_encrypted)`). `mask_secret` takes `&str` or `Option<&str>` (the JS `null`).
  The derived key is cached per `App`.
- **`key_vault`**: `set_key(app, name, value, description: Option<&str>)` returns `anyhow::Result<SetKeyResult>`;
  `get_key` returns `Result<Option<String>, VaultError>`; `list_keys` returns `Vec<KeyInfo>` (serialises to the JS
  field names); `get_all_keys_decrypted` returns `Vec<(String, Option<String>)>` in the file's order;
  `vault_file(app)` is the JS `VAULT_FILE`.
- **`security_manager`**: `get_security_manager(app, &dyn Settings)` gives the app's one manager.
  `set_tool_permission(&dyn Settings, tool, mode)` takes the settings again, because the manager does not keep the
  store (the JS kept the first one it was given). A mode is a `serde_json::Value`: the admin route stores whatever
  it is sent, and `get_tool_permission(..) == "always_deny"` compiles as it reads. `check_tool_permission` returns
  `ToolVerdict { allowed, reason, warning }`. `validate_tool_input` returns `Result<ToolValidation, FilenameNotText>`
  (see "Looks like a bug", 3). `sanitize_env(&Env)` works on an `Env`, never the real environment.
- **`middleware::auth`**:
  - `initSessionStore(db)` is `SessionStore::init(app) -> anyhow::Result<Arc<SessionStore>>` (creating the table can
    fail; the JS let that throw at boot). `SessionStore::of(app)` and `AuthAttempts::of(app)` make the services on
    first use, as the JS had them from import.
  - The middleware are `session_auth`, `require_auth`, `rate_limit_auth`, for
    `axum::middleware::from_fn_with_state(app, ...)`. `req.auth` is the `Auth` request extension, also an extractor
    (`Auth { authenticated, method: Option<AuthMethod>, session_id }`, serialising to the JS object). For a route
    file, which has no `App` when it builds its router, there are the extractors `RequireAuth(Auth)` and
    `ClientIp(Option<String>)`. `authenticate(app, headers)` is the body of `sessionAuth`.
  - Functions that took `req` take `&HeaderMap`: `live_session_id`, `sign_in_ended`,
    `validate_session_from_request`.
  - **The client address (`req.ip`) is `middleware::auth::client_ip(headers, extensions) -> Option<String>`**, and
    the `ClientIp` extractor over it: the last address in `X-Forwarded-For` as Express gave it with one trusted
    hop, else `ConnectInfo<SocketAddr>`, else `None`. Route packages should use it wherever the Node code read
    `req.ip`.
  - `record_failed_attempt` and `clear_failed_attempts` take `ip: Option<&str>` (the JS passed `req.ip`, which can
    be undefined). `sign_in_ran_out(what: Option<&str>)`. `session_max_age_ms` and `session_cookie_max_age_ms`
    return `f64`, because the lifetime is `Number(env) * 86400000` and need not be whole.
  - `Clock` (`Clock::of(app)`, `Clock::manual(ms)`) is where this package reads `Date.now()`; a test stores a manual
    one in the app before anything reads the time. The two sweeps run on `tokio::time` intervals.
- **`middleware::security`**: `security_headers`, `generate_csrf_cookie`, `csrf_protect` are middleware functions.
  Added: `Csrf::of(app)` (the secret and lifetime), `csrf_cookie(app)`, and `cookie(name, value, options, now_ms)`
  and `clear_cookie(name)`, which give the `Set-Cookie` line Express's `res.cookie` and `res.clearCookie` wrote.
- **`routes::auth_routes`**: `authRouter` is `router() -> Router<App>` with `/login`, `/api-token`, `/logout`,
  `/csrf`, `/status`. The login handler reads the body as `express.json` did and then calls the rate limiter
  itself (`AuthAttempts::rate_limit`), which is the Node order: `express.json` ran before `rateLimitAuth`, so a
  body that is not JSON was never counted as an attempt.
- **`db::audit`**: `AuditLog::init(app)` stores it (`app.set("auditLog", ...)`); code that logs uses
  `app.get::<AuditLog>()` and does without when there is none. `log` takes an `AuditEntry` (`AuditEntry::new(action)
  .actor(..).ip(..)`). `query(limit: Option<i64>, offset: Option<i64>)` returns rows as JSON objects.
- **`lib::loop_guard`**: `create_loop_guard() -> LoopGuard` with `on_call`, `on_result(id, ok: bool)`,
  `check() -> Option<String>` (the JS `false` is `None`) and `count()`.
- **`ai::agent_env`**: `agent_vault_env(app, AgentVaultEnvOptions { names, get, list, env, now, denied })` returns
  `Arc<BTreeMap<String, String>>` (the cached answer is the same `Arc`). `env` is a `&BTreeMap`; without one the
  app's `Env` is compared against. `__resetAgentEnv` is `reset_agent_env(app)`.

## Differences from the Node behaviour

1. **JSON responses say `Content-Type: application/json`** (axum's `Json`, as the foundation's `ApiError` does);
   Express's `res.json` said `application/json; charset=utf-8`. One decision for every route, so left to the lead.
2. **POST `/login` with a body that is not valid JSON** is a 400 `{ "error": message }` as before, but the message
   is `serde_json`'s, not V8's. A body that is valid JSON but not an object or array gets V8's words
   (`Unexpected token 'h', "hello" is not valid JSON`; where V8 named half of a first emoji, the whole one is
   named). Also: a `charset` other than utf-8 is always a 415 (Node
   decoded utf-16, utf-32 and utf-7); a compressed body (`Content-Encoding`) is not inflated; an escape of half a
   surrogate pair is refused by the parser.
3. **The 500 for an error the Node code let escape** (see "bug" 1, and a cookie lifetime no cookie can carry) is
   built in `middleware::security::uncaught_error`: same status, body and `[error]` line, but no stack in the log
   and nothing recorded for self-heal (`recordError`, package A4).
4. **A cut through an emoji** in `mask_secret` leaves the emoji out (the foundation's `utf16_slice`); JavaScript
   kept half of it.
5. **A hand-edited `vault.json`**: one that is JSON but not an object is an empty vault (Node threw, or lost the
   write); a `value`, `description` or date that is not text counts as absent.
6. **`get_tool_permission` for a tool named like a member of `Object.prototype`** ("constructor", "toString")
   gives "always_allow"; the JS lookup gave the function. A tool whose name is a whole number is listed in the
   order it was set; a JS object lists such keys first.
7. **A cookie expiring after the year 262142** is refused as "option expires is invalid"; Node managed to 275760.
   It takes `TARSEE_SESSION_MAX_AGE_DAYS` above 95 million.
8. **`set_rate_limit` takes a whole number** (`u32`). Nothing in Tarsee calls it.
9. The security headers are added to the response after the handler ran, and only where the handler set none
   (the Node code set them first and a handler overwrote them): the same headers, in another order on the wire.
10. The two sweeps start with the first use of their service inside a tokio runtime, not at import. The
    "[auth] ... sweep failed" log lines are gone: a sweep here has nothing left that can fail.

## Looks like a bug in the Node code

Ported as it is in every case.

1. **A CSRF token whose signature has the wrong length is a 500, not a 403.** `verifyCsrfToken` hands
   `crypto.timingSafeEqual` two buffers of different lengths, which throws. Any stale or cut token with a fresh
   timestamp does it, and so does the header sent twice.
2. **A request without an address is rate-limited under "unknown" but its failures are filed under `undefined`**
   (`rateLimitAuth` uses `req.ip || ... || "unknown"`, `recordFailedAttempt(req.ip)` does not), so the lockout
   never reaches it. `AuthAttempts` keys on `Option<String>` to keep that.
3. **`validateToolInput` throws when `write_file` gets a `filename` that is a number, `true` or an object**, and
   `tools.js` catches that around both the validation and the permission check: such a call skips the policy
   altogether. `validate_tool_input` returns `Err(FilenameNotText)`; package S3 decides whether to keep the skip.
4. **`http://[::ffff:127.0.0.1]/` passes the private-address check.** The URL's hostname is `[::ffff:7f00:1]`,
   which no pattern in `PRIVATE_IP_REGEX` covers: IPv4-mapped loopback and private addresses get through
   `web_fetch` and `browser`. The same pattern also refuses public names by prefix (`10.example.com`,
   `127.0.0.1.nip.io`).
5. `DANGEROUS_COMMANDS` flags "résudo" and "pre-sudo-post": JavaScript's `\b` sees only ASCII letters.
6. The session sweep drops what is older than the lifetime, while `isLiveSession` ends a sign-in at exactly the
   lifetime: one millisecond apart.
7. The CSRF secret is derived from `process.env.ENCRYPTION_KEY` as set, the vault key from the trimmed
   `config.ENCRYPTION_KEY`. Kept, so that a token the Node version signed still verifies.
8. `agentVaultEnv` treats a call with its own `list` but the default `get` and `env` as the default call, and
   caches it.
9. `getSecurityManager(store)` kept the first store it was given; had the first caller passed none, saved
   permissions never loaded.

## Dependencies added

- `[dev-dependencies] tokio = { version = "1.54.1", features = ["test-util"] }`. `#[tokio::test(start_paused =
  true)]`, which DESIGN.md tells every package to use for timers, does not compile without it. As a dev-dependency
  it is not part of a normal build. It rebuilds tokio and what depends on it once for the test profile.

No new crate. PBKDF2 is written out over `hmac` and `sha2` (about 20 lines, checked against Node's
`crypto.pbkdf2Sync`) rather than adding `pbkdf2`.

## Changes needed outside this package

- **Foundation.** `Clock` lives in `middleware::auth` for want of a better place; `src/util/` would suit it, since
  other packages with timers need the same. The same goes for the JavaScript helpers that are `pub(crate)` in
  `middleware/auth.rs` and `middleware/security.rs`: `js_number` (`Number(text)`), `js_trim`, `JS_WHITESPACE`
  (the `\s` class), `js_number_to_string` (exact `String(number)`, exponent forms included; `util::js::
  number_to_string` is not exact there) and `node_header` (a request header as Node's `req.headers` gave it).
- **An `express.json()` for the whole server.** The Node server parsed every body before any route: only
  `application/json`, object or array only, 400 with the parser's message, 415 for a bad charset, 50 MB. The login
  route has its own copy (`auth_routes::json_body`); the route packages need one rule. axum's `Bytes` and `Json`
  stop at 2 MB unless the server sets `DefaultBodyLimit`.
- **Z1 (`server.rs`)**: call `SessionStore::init(&app)?` right after the database is open and `AuditLog::init(&app)`;
  serve with `into_make_service_with_connect_info::<SocketAddr>()`, or `client_ip` has only the header to go by;
  layer `security_headers` outermost, then `session_auth`; `generate_csrf_cookie` on page loads; nest
  `auth_routes::router()` at `/api/auth` with neither `require_auth` nor `csrf_protect`; on the API routers
  `require_auth` runs before `csrf_protect` (`.layer(csrf_protect).layer(require_auth)`). The WebSocket upgrade
  has `validate_api_token`, `validate_session_from_request`, `live_session_id` and `is_live_session`.
- **A4 (`middleware/error_handler.rs`)**: `security::uncaught_error` should go through it once it exists.
- **S1**: `SettingsStore` only has to implement `Settings` for `get_security_manager(app, &store)`.
- **S3**: mirror the JS `try/catch` around `validate_tool_input` and `check_tool_permission`.
- **G1, G2**: `agent_vault_env(app, AgentVaultEnvOptions { env: Some(&map), denied: Some(&|| ...),
  ..Default::default() })`.

## Risks

1. **`Cargo.toml`**: the dev-dependency above. Other batch 1 packages may have added the same line.
2. **The vault's crypto path**: the hand-written PBKDF2, Node's lenient base64 reading (`node_base64_decode`), and
   the IV length. Tarsee writes 16-byte IVs, but Node decrypts 1 to 128 bytes, and the cipher's IV length is part
   of its type here, so `open_any` has one arm per length (128 small instantiations). All of it is pinned by the
   Node fixtures; a reviewer should look here first.
3. **`client_ip` believes the last `X-Forwarded-For` entry whoever connects**, exactly as Express did with
   `trust proxy` 1. Run without a proxy in front, a client picks its own rate-limit key. Same in the Node version.
4. **The services capture the app's `Clock` when they are made.** A test must store its manual clock first; one
   stored later is ignored without a word.
5. **Sign-in state is per `App`.** Anything that builds a second `App` over the same database gets its own
   sessions map (hydrated from the table) and its own attempt counts.
6. **Exactness of the JavaScript helpers** (`js_number`, `js_number_to_string`, `utc_string`): they decide the CSRF
   500 versus 403, the lifetimes read from the environment, and the cookie lines. Each is tested against a table of
   Node's own answers.
7. **The suite was run on Windows only.** Nothing in the package branches on the platform, but the one test that
   is `#[cfg(unix)]` (`vault.json` is created with mode 0600) has not been run.
